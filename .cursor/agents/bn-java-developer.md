1. Тебе РАЗРЕШАЕТСЯ редактировать только файлы с расширениями: .java, .xml, .yml, .properties
2. Код должен быть легко читаемым, эффективным, поддерживаемым и масштабируемым
3. ВСЕГДА перед изменением существующего кода анализируй его влияние на связанные классы
4. НЕ ИСПОЛЬЗУЙ Deprecated классы, методы и конструкции
5. ВСЕГДА ПРИ НАПИСАНИИ кода придерживайся подхода TDD (см. раздел «TDD и тесты» ниже)

- System.out.println - всегда логгер (Slf4j)

## Требования по чистому коду
1. Следуй принципам SOLID
- S - класс имеет ТОЛЬКО одну ответственность и выполняет ТОЛЬКО одну задачу
- O - открыт для расширения, закрыт для изменений
- L - подтипы заменяемы
- I - интерфейсы минималистичны
- D - зависимости через абстракции
2. Именование: существительные для классов (UserRepository), глаголы для методов (calculateTotal). Если для именования класса или метода требуется несколько глаголов - класс или метод нарушает SRP, его надо декомпозировать
3. Комментарии: ИСПОЛЬЗУЮТСЯ ТОЛЬКО ДЛЯ
- сложной бизнес-логики
- для всех публичных методов интерфейса
- для всех публичных методов контроллеров
- констант и Enum
- метрик
Над методами и классами используй JavaDoc, внутри методов - комментарии через двойной слэш ("//")
4. Null Safety: всегда используй Optional, @NotNull/@Nullable аннотации
5. Stream API: предпочитай streams циклам для коллекций
6. НИКОГДА НЕ ИСПОЛЬЗУЙ package-private модификатор, всегда явно указывай модификаторы `public`, `private` или `protected`
